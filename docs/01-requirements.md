# Требования к продукту «Шаурма-Мастер»

## 1. Цель продукта

Дать клиенту возможность заказать шаурму с доставкой или самовывозом за минимум действий, а ресторану — принимать и обрабатывать заказы.

## 2. Роли

| Роль | Возможности |
|---|---|
| Гость | Смотрит меню, собирает корзину, оформляет заказ без регистрации |
| Покупатель | Всё, что гость + история своих заказов |
| Администратор | Управляет заказами (статусы), меню, видит статистику |

## 3. User stories

### US-01. Просмотр меню

**Как** гость, **я хочу** видеть меню с категориями и ценами, **чтобы** выбрать блюдо.

Критерии приёмки:
- Меню сгруппировано по категориям, отсортировано по `sortOrder`.
- В карточке: название, описание, цена, вес, признак остроты.
- Недоступные товары не показываются в витрине.
- Пустая категория показывает заглушку.

### US-02. Дополнители

**Как** покупатель, **я хочу** добавлять дополнительные ингредиенты, **чтобы** настроить блюдо под себя.

- Дополнители доступны при добавлении товара в корзину.
- Цена позиции = (цена товара + сумма дополнителей) × количество.
- Один товар с разными дополнителями — разные позиции корзины.

### US-03. Оформление заказа

**Как** гость, **я хочу** оформить заказ без регистрации.

- Обязательные поля: имя, телефон, адрес (при доставке).
- Телефон валидируется: 10–15 цифр.
- При доставке сумма ≥ 500 ₽.
- После оформления возвращается номер вида `SH-ГГММДД-ХХХХ`.
- Заказ получает статус `NEW` и запись в истории.

### US-04. Промокоды

**Как** покупатель, **я хочу** применить промокод, **чтобы** получить скидку.

- Промокод регистронезависим.
- Неактивный → `PROMO_INACTIVE`, просроченный → `PROMO_EXPIRED`, лимит → `PROMO_LIMIT_EXCEEDED`.
- Скидка округляется вниз до целого рубля.

### US-05. Отслеживание заказа

- По `publicId` доступна информация о заказе и истории статусов.
- Несуществующий номер → 404.

### US-06. Обработка заказов

**Как** администратор, **я хочу** менять статус заказа.

- Переходы только по разрешённой цепочке.
- Недопустимый переход → 409 `INVALID_STATUS_TRANSITION`.
- Каждая смена статуса пишется в историю.
- Покупатель не имеет доступа к админским методам (403).

### US-07. Управление меню

- Удаление мягкое: товар скрывается, но остаётся в старых заказах.
- Цена — положительное целое число.
- Нельзя создать товар в несуществующей категории.

## 4. Бизнес-правила

| ID | Правило |
|---|---|
| BR-01 | Минимальная сумма заказа с доставкой — 500 ₽ |
| BR-02 | Самовывоз без минимальной суммы |
| BR-03 | Скидка считается от суммы товаров, округление вниз |
| BR-04 | `NEW → CONFIRMED → COOKING → DELIVERING → DONE`; отмена из любого, кроме `DONE` и `CANCELLED` |
| BR-05 | Товар с `isAvailable = false` заказать нельзя |
| BR-06 | Лимит использований промокода учитывается суммарно |
| BR-07 | Пароль не короче 6 символов |
| BR-08 | Email уникален |

## 5. Коды ошибок API

| Код | HTTP | Когда |
|---|---|---|
| `VALIDATION_ERROR` | 400 | Не прошла валидация |
| `INVALID_CREDENTIALS` | 401 | Неверный email/пароль |
| `UNAUTHORIZED` | 401 | Нет или истёк токен |
| `FORBIDDEN` | 403 | Не хватает прав |
| `NOT_FOUND` | 404 | Объект не найден |
| `EMAIL_TAKEN` | 409 | Email занят |
| `MIN_ORDER_AMOUNT` | 409 | Сумма ниже минимума |
| `PRODUCT_UNAVAILABLE` | 409 | Товар недоступен |
| `PROMO_INACTIVE` / `PROMO_EXPIRED` / `PROMO_LIMIT_EXCEEDED` | 409 | Проблема с промокодом |
| `INVALID_STATUS_TRANSITION` | 409 | Недопустимый переход статуса |
| `INTERNAL_ERROR` | 500 | Необработанная ошибка |

## 6. Нефункциональные требования

- Ответ API не дольше 500 мс локально.
- Все ответы содержат `X-Request-Id`.
- Ошибки не раскрывают стек вызовов.
- Запуск одной командой.

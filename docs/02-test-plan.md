# План тестирования «Шаурма-Мастер»

## 1. Объект тестирования

Веб-приложение интернет-магазина шаурмы: REST API, витрина (SPA на vanilla JS), админ-панель.

## 2. Цели

1. Проверить соответствие функциональности требованиям (`01-requirements.md`).
2. Найти дефекты в бизнес-логике заказа, промокодов и статусной модели.
3. Проверить безопасность доступа к админским методам.
4. Обеспечить регрессионную защиту перед релизом.

## 3. Что тестируем

| Модуль | Приоритет | Виды проверок |
|---|---|---|
| Меню и товары | Высокий | Функциональное, UI |
| Корзина | Высокий | Функциональное, расчёты |
| Оформление заказа | Критический | Позитивные/негативные, граничные значения |
| Промокоды | Высокий | Эквивалентные классы |
| Статусы заказа | Высокий | Таблица переходов |
| Аутентификация и права | Критический | Негативные, security |
| Админка | Средний | Функциональное, UI |
| API-контракт | Высокий | Коды ответов, формат ошибок |

**Не тестируем в этой итерации:** оплату (не реализована), реальную доставку, интеграции с внешними сервисами, нагрузку выше 100 RPS.

## 4. Подход

### Уровни

| Уровень | Инструмент | Что покрывает |
|---|---|---|
| Smoke | `node:test` | Доступность, меню, health |
| API-тесты | `node:test` + fetch | Контракт, бизнес-правила, негатив |
| UI (ручное) | Браузер + DBeaver | Витрина, корзина, оформление, админка |
| E2E (план) | Playwright | Сквозной сценарий покупки |

### Техники тест-дизайна

- **Эквивалентные классы** — суммы заказа, телефоны, промокоды.
- **Граничные значения** — 499/500/501 ₽, количество 0/1/20/21.
- **Таблица переходов** — статусы заказа.
- **Попарное тестирование** — доставка × промокод × авторизация.
- **Анализ рисков** — где деньги, там и баги.

## 6. Тестовые данные

См. [07-test-data.md](07-test-data.md). Демо-данные создаются автоматически при старте.

## 7. Критерии входа (DoR)

- Сборка запускается локально.
- База наполнена демо-данными.
- Известны тестовые учётки и промокоды.

## 8. Критерии выхода (DoD)

- Пройдено 100% smoke-тестов.
- Пройдено не менее 95% тест-кейсов высокого приоритета.
- Нет открытых багов уровня Blocker/Critical.
- Автотесты зелёные: `npm test` → 24/24.

## 9. Риски

| Риск | Влияние | Митигация |
|---|---|---|
| Нет транзакций при создании заказа | Частично записанный заказ | Проверка при сбое, баг-репорт BUG-001 |
| JWT живёт 24 часа, нет refresh | Обрыв сессии | Негативные тесты токена |
| Публичный доступ к заказу по номеру | Утечка данных | BUG-003 |
| Промокод не резервируется | Гонка при конкурентном применении | Нагрузочный тест |

## 10. Метрики

- Покрытие требований тест-кейсами — 100%.
- Плотность дефектов на модуль.
- Время прогона регрессии (сейчас ~2 сек на API-набор).

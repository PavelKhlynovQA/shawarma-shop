Общая картина

База нормализована до третьей нормальной формы. Девять таблиц: четыре справочника, две транзакционные, две служебные и одна для одноразовых кодов.

Таблицы

usersПользователи: админ и покупателиid, email, password_hash, name, phone, role

otp_codesКоды входа по телефонуid, phone, code, expires_at, attempts, used

Связи

  • categories 1 — N products (products.category_id → categories.id)
  • users 1 — N orders (orders.user_id → users.id, может быть NULL для гостя)
  • orders 1 — N order_items (каскадное чтение по order_id)
  • orders 1 — N order_status_history
  • order_items.product_id — ссылка на товар, но название и цена хранятся снимком

Правила целостности

  • subtotal заказа равен сумме line_total всех позиций
  • total = subtotal − discount
  • orders.status совпадает с последней записью в order_status_history
  • После успешного входа otp_codes.used = 1, при неверном коде растёт attempts
  • Удаление товара мягкое: is_available = 0, запись остаётся для старых заказов

Примечание. Проверки целостности оформлены как SQL-тест-кейсы TC-DB-01…TC-DB-08 и выполняются вручную в DBeaver после каждого релиза.

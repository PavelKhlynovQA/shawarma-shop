Подход

Тестирование строится по пирамиде: много быстрых проверок API, меньше сквозных UI-сценариев, отдельно визуальная регрессия и разовые ручные проверки БД. Цель — ловить дефекты как можно ближе к источнику.

Что тестируем в первую очередь

  • Деньги: суммы заказа, скидки, минимальная сумма доставки
  • Статусная модель: невозможность недопустимых переходов
  • Доступ: гость не может в админку, покупатель не может в админку
  • Персональные данные: кто видит заказ
  • Хрупкие места: расчёт с дополнителями, промокоды, оплата

Критерии входа и выхода

  • Вход: сборка запускается, база наполнена, известны тестовые данные
  • Выход: smoke 100%, кейсы высокого приоритета ≥95%, нет Blocker/Critical
  • Все автотесты зелёные в CI: API 23/23, E2E 35/35, визуальные 5/5

Обзор

Монолитное веб-приложение на Node.js: один процесс отдаёт и API, и статические файлы витрины. Такое решение выбрано осознанно — проект учебный, важно показать архитектурные границы, а не распределённость.

Компоненты

  • Веб-клиент: витрина (index.html + app.js) и админка (admin.html + admin.js)
  • HTTP-сервер Express 4: 20 эндпоинтов под префиксом /api
  • Слой данных: адаптер с двумя драйверами — PostgreSQL (Docker) и SQLite (локально)
  • База: 9 таблиц, история статусов и одноразовые коды входа
  • CI: GitHub Actions — API-тесты, E2E, визуальные тесты, сборка образа

Поток оформления заказа

  • 1. Клиент отправляет POST /api/orders с позициями и данными получателя
  • 2. Сервер проверяет товары, дополнители, минимальную сумму и промокод
  • 3. Считает subtotal, discount, total и создаёт заказ со статусом NEW
  • 4. Пишет позиции в order_items и запись в order_status_history
  • 5. Клиент оплачивает: POST /api/orders/{publicId}/pay — статус оплаты PAID
  • 6. Администратор меняет статус: CONFIRMED → COOKING → DELIVERING → DONE
  • 7. Экран клиента опрашивает заказ каждые 2 секунды и показывает уведомление

Развёртывание

  • Docker Compose: два контейнера — shawarma-app (Node 24) и shawarma-db (PostgreSQL 16)
  • Приложение поднимается после healthcheck базы
  • Порты: 3000 — приложение, 5432 — база
  • Данные базы хранятся в именованном томе pgdata
  • Локальный режим: npm start поднимает приложение на SQLite без Docker

Известные архитектурные ограничения

  • Нет транзакций при создании заказа — при сбое возможен заказ без позиций (BUG-006)
  • Нет горизонтального масштабирования: один процесс, сессии в JWT
  • Нет очереди на уведомления — опрос статуса вместо событий
  • Публичный доступ к заказу по номеру (BUG-005)

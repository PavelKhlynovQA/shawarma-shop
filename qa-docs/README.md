# QA-документация проекта

Готовые артефакты для портфолио: их можно разложить по Confluence и Jira за 15 минут.

## Что внутри

| Папка | Что это |
|---|---|
| `site/index.html` | Полная документация одним файлом: открыть в браузере, распечатать в PDF |
| `confluence/*.html` | 10 страниц в формате Confluence Storage Format |
| `jira/test-cases.csv` | 53 тест-кейса для импорта |
| `jira/bug-reports.csv` | 10 баг-репортов |
| `content/*.mjs` | Исходные данные — правь и пересобирай: `npm run docs:build` |

## Как перенести в Confluence

1. Создай пространство, например **QA · Шаурма-Мастер**.
2. Для каждой страницы: **Создать страницу** → меню «⋯» → **Вставить разметку** (Insert markup / Storage format).
3. Вставь содержимое соответствующего файла из `confluence/` → **Сохранить**.
4. Порядок страниц: 00 → 01 → 02 → 03…09. Дочерние страницы вложи под «Главную».

Альтернатива: **Администрирование → Импорт → HTML** (если доступен плагин импорта).

## Как перенести в Jira

1. **Настройки Jira → Система → Внешний импорт (External System Import) → CSV**.
2. Загрузи `jira/test-cases.csv`, формат — UTF-8.
3. Замапь колонки:
   - `Issue Type` → Issue Type
   - `Summary` → Summary
   - `Priority` → Priority
   - `Labels` → Labels
   - `Steps` + `Expected Result` → Description
4. Для багов повтори с `bug-reports.csv`, Issue Type = Bug.

Если стоит **Xray** или **Zephyr** — Issue Type `Test` импортируется сразу как тест-кейс, а `Steps` подхватится в шаги.

## Как пересобрать

```bash
npm run docs:build
```

После правки данных в `content/` — сайт, страницы Confluence и CSV пересоздадутся.

## Принцип

Каждый тест-кейс связан с требованием (`FR-xx`) и с автотестом (`E2E-xx`, `api.test.js`). Это и есть трассировка — она показывает, что документация не написана «в стол», а по ней действительно писались автотесты.

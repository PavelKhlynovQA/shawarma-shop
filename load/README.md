# Нагрузочное тестирование

Профиль нагрузки для Apache JMeter 5.6.3. Проверяет витрину, корзину и оформление заказа под одновременной нагрузкой.

## Что в каталоге

| Файл | Назначение |
|---|---|
| `plan.jmx` | План теста: три группы потоков и HTTP-запросы |
| `metrics.json` | Метрики последнего прогона (запросов, RPS, перцентили, ошибки) |
| `presentation/` | 7 слайдов с результатами |
| `results.jtl` | Сырые результаты прогона (в git не хранится) |

## Профиль нагрузки

| Группа | Потоков | Ramp-up | Длительность | Запросы |
|---|---|---|---|---|
| Каталог | 15 | 10 с | 60 с | `GET /api/menu`, `GET /api/products/1` |
| Корзина | 5 | 5 с | 60 с | `GET /api/cart`, `POST /api/cart/items` |
| Заказы | 1 | 1 с | 60 с | `POST /api/orders` |

Итого 21 виртуальный пользователь, суммарная длительность около 70 секунд.

## Запуск

```bash
# приложение должно быть запущено на http://localhost:3000
jmeter -n -t load/plan.jmx -l load/results.jtl -j load/jmeter.log
```

Параметры хоста и порта заданы переменными `host` и `port` в Test Plan — можно переопределить через `-Jhost=... -Jport=...`.

Разбор результатов:

```bash
node .tmp/parse-load.mjs      # формирует load/metrics.json
node .tmp/build-slides.mjs    # пересобирает слайды
```

## Ограничения

- Нагрузка шла с той же машины, где работает приложение: результаты занижены по CPU и сети.
- Одна нода PostgreSQL без реплик, соединения не пулятся отдельным пулом.
- Soak-тест на 30 минут и стресс-тест до отказа не проводились — вынесены в бэклог.

# Передача проекта на ревью

## Что это

Учебный интернет-магазин шаурмы «ШаурмаМастер» — полигон для портфолио QA-инженера.
Реальный backend, база данных, витрина, админка, автотесты и полный набор тест-документов.

- Репозиторий: https://github.com/PavelKhlynovQA/shawarma-shop (публичный)
- Jira: https://boysporting.atlassian.net/jira/software/projects/SCRUM (приватный)
- Confluence: https://boysporting.atlassian.net/wiki/spaces/QASHOP (приватный)

## Что в этом пакете

| Файл | Что внутри |
|---|---|
| `ALL-TEST-CASES.md` | Все 66 тест-кейсов одним файлом: 31 в новом формате v2, 35 в старом v1 |
| `jira-export.csv` | 81 задача Jira с полными описаниями (включая эпики и кейсы) |
| `HANDOVER.md` | Этот файл: состояние проекта и что ревьюить |

Остальное — в репозитории: код (`src/`), автотесты (`tests/`), документация (`docs/`), генераторы документации (`qa-docs/`).

## Стек и запуск

Node.js 24+, Express 4, PostgreSQL 16 или SQLite, чистый JS без сборки, Docker Compose.

```bash
git clone https://github.com/PavelKhlynovQA/shawarma-shop.git
cd shawarma-shop
npm install
npm start            # http://localhost:3000, SQLite
# или
docker compose up -d # PostgreSQL на том же порту
```

Учётки: `admin@shawarma.ru / Admin123!`, `customer@test.ru / Test123!`.
Вход по телефону — код показывается на экране (SMS не отправляется).

Тесты: `npm test` (23 API), `npm run test:e2e` (35 Playwright), `npm run test:visual` (5).

## Состояние тест-документации

Проект в процессе перевода тест-кейсов на новую концепцию. Есть два формата.

### v2 — новая концепция (31 кейс)

Модули: Витрина (10), Корзина (6), Авторизация (3), Оформление (3), Оплата (2), Уведомления (1), Администрирование (6).

Принципы: атомарность (один кейс — одна проверка), шаги только действия пользователя, ожидаемый результат измерим, динамические данные через эталонные таблицы (ТД-1…ТД-8), сетевые проверки отдельным блоком.

### v1 — старый формат (35 кейсов)

API (27) и БД (8). Написаны как монолиты: несколько проверок в одном кейсе, точные числа захардкожены, шаги содержат «проверить».

## Что осталось сделать

1. **Перевести API-модуль** (27 кейсов) на v2. Основная сложность: многие кейсы проверяют 3–5 идей сразу — требуется разложение на 35–40 атомарных.
2. **Перевести модуль БД** (8 кейсов) — разложение минимальное, по одному SQL-запросу на кейс.
3. **Обновить матрицу трассируемости** в Confluence под новые ID.
4. **Синхронизировать Confluence** — страницы «Тест-кейсы» сейчас индексируют Jira, но заголовки задач изменились.

## Спорные решения — на что смотреть ревьюеру

1. **Терминология ID.** Смешаны две схемы: `TC-UI-*` (старая) и `TC-SHOP/CART/AUTH/*` (новая). Вопрос: оставить модульные префиксы или вернуться к единому `TC-*`?
2. **Эталонные таблицы.** Динамические значения (число товаров, цены) вынесены в ТД-1…ТД-8. Но сами таблицы в Jira не заведены — кейсы ссылаются на них, а расшифровка только в Confluence.
3. **Сеть в ожидаемом результате.** Для v2 выбран формат: UI-часть в таблице, запросы — отдельным блоком ниже. Альтернатива — держать всё в ячейке (получалось нечитаемо).
4. **Приоритеты.** Шкала High/Medium/Low, но в Jira поле «Приоритет» заполнено как Medium у всех задач — расхождение не устранено.
5. **Скриншоты.** Приложены к каждому кейсу, но часть — синтетические карточки (для API и БД), а не реальные экраны.
6. **Автотесты не проверены после правок документации** — код не менялся, но прогон не выполнялся.
